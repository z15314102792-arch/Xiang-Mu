# 项目经历｜AI 口播工作流质量治理

> 用于简历项目介绍与面试准备；区分历史项目事实、当前公开演示、尚未完成的自动剪辑能力。

## 30 秒介绍

在口播 AI 辅助剪辑实验中，遇到了自动字幕断句不符合语义、花字为凑数量乱加、音效机械跟随花字，以及口误/废片无法可靠识别的问题。我的主要工作是把这些主观反馈拆解为可描述、可记录、可复测的规则和验收项，维护问题清单，逐轮对照成片复核。后来将质量门槛、固定回归用例和规则锁定结合起来，减少修复一个问题又引发另一个问题的情况。由于不同素材特别是双说话人处理仍不稳定，原项目未完成全自动交付；这份公开演示重点呈现已形成的治理与测试方法。

## 发生过程

| 阶段 | 做过什么 | 沉淀 |
|---|---|---|
| 1. 确定问题 | 人工口播剪辑重复劳动高、效果不一致 | 把剪辑质量变成需要验收的目标 |
| 2. 分析参考 | 参考库 84 条口播成片，抽查字幕、花字、声音、节奏 | 样本观察与目标风格 |
| 3. 拆解工作流 | 粗剪、字幕、花字、音效、封面/包装 | 业务节点和质量标准 |
| 4. 记录失败案例 | 将反馈拆为单一问题、明确影响和修复要求 | 高频坏案例和问题分类 |
| 5. 固定规则 | 防止花字凑数、固定时长错位、SFX 绑花字、ASR-only 留废片 | 独立业务规则 |
| 6. 规则治理 | 单项规则锁定、变更记录、回滚设计以及历史回归 | 31 条历史规则、15→17 项历史回归记录 |
| 7. 实际验收 | 机械检查和真人看成片分开 | 技术通过 ≠ 用户认可 |
| 8. 收敛作品集 | 从原私有工程抽取无私有内容的场景 | 8 条演示规则、9 个模拟案例、网页质检器 |

**数据口径说明**：历史 31 条规则、15/17 项回归是原工程的阶段记录；本仓库只包含独立演示的 8 条规则、9 个模拟案例，不把历史数据当成本仓库实测结果。

## 如何讲一个具体问题

**花字乱加**：某一版为了达到预设密度，把普通叙述当作重点。反馈并不只是“感觉不好看”，而是“规则把数量当成了目标”。于是把花字候选限制为核心观点和有观看价值的总结，普通叙述必须舍弃，并保留这个坏案例用于复测。

**花字时机**：某一版把花字统一设成约 1.2 秒，实际讲话时长不同，导致提前消失。因此改为按真实词级起止决定出现和结束，禁止固定时长模板。

**音效机械化**：早期音效直接按花字索引派生，内容没到重点就响了。将 SFX 决策与花字拆开，以语义、重音、动作等触发条件判断。

**废片残留**：ASR 能识别说出的话，却不能可靠识别出错动作、失败重说或咳嗽。因此粗剪验收增加音频与画面双重核查，不再用“转写没有错误”替代成片复核。

## 角色边界

- **我负责**：目标判断、真实样本反馈、业务规则定义、优先级取舍、验收要求、结果评估。
- **AI 协助**：代码编写、算法调试、文件解析、部分自动化检查、测试脚本实现。
- **没有完成**：把所有人声和镜头自动分离并稳定导出商业成片；最近的新素材中 IP 和操盘手区分仍失败。
- **不能主张**：真实客户部署、节省了多少人工小时、通用剪辑系统上线、自动质检代替人审，除非未来有额外证据。

## 面试时建议现场做的演示

先选一个失败案例让系统指出问题及关联规则，再选正常案例说明“机械通过只是进入人工审核”，最后修改一处 JSON 重新运行。重点解释**为什么要这样设计规则**，而不是假装所有代码都由自己独立手写。

## 公开版与原项目的关系

当前仓库是 **脱敏、重建的教学/作品集演示**，不是直接拷贝整个私有工程。公开版的规则 ID、治理思想与错误类型来自原项目，但输入数据为合成案例，检查算法是为可移植演示重新实现的简化版本。实际媒体处理及历史回归需要在私有环境独立验证。

## v1.1：从演示型作品到可执行的视频工具（2026-10-28）

用户明确要求：上线 GitHub 不能只有页面和假数据，应能处理真实视频并产出可用结果。原 v1.0 只能演示规则治理，不能算完整产品，因此新增一个独立的真实媒体工作台。

- 输入：用户本地选择并导入真实 MP4 等视频。
- 自动部分：FFprobe 读取元信息；FFmpeg 检测静音、给出候选保留区间；可选本地 Whisper tiny/small 语音转写。
- 人工环节：播放原片，对片段起止点、IP/操盘手、删除决定和字幕文本进行人工复核。
- 真正执行：FFmpeg 按用户确认的时间段重编码并连接成片，输出 H.264/AAC MP4；SRT 重映射到剪辑后时间轴，附基础质检报告。
- 验收：真实生成含音轨和停顿的测试视频，执行上传 / 分析 / 编辑 / 导出，验证新 MP4 时长、音轨、字幕和 HTTP Range 播放；旧模拟回归测试仍保留在 /demo。
- 已知缺口：尚不具备可靠自动说话人分离、自动口误识别、花字/BGM/SFX/封面的完整自动包装。当前属于**真实可使用的辅助粗剪与字幕工具**，不是商业化全自动剪辑流水线。

对面试的说法：从一开始的 AI 剪辑自动化尝试，逐步建立了规则和历史问题回归，后因仅展示规则缺乏实用价值，又将成果落成可直接导入视频、人工复核和输出实际成片的本地工具。过程中负责业务需求、质量门槛、取舍与验收，代码由 AI 辅助实现。

## v1.2｜字幕/花字动画/音效包装的真实可用闭环（2026-10-28）

- 触发原因：用户指出 v1.1 仍停留在粗剪后导出，没有字幕烧录、花字和动画、音频包装；实际制作口播成片价值不足，要求不是只有展示功能，而要能实际制作。
- 新版真实能力：字幕 ASS 硬烧录，支持字号、颜色、底部位置及淡入、轻弹动画；可逐条编辑花字文案、成片时间轴起止、位置、颜色、弹入/淡入/上浮动画；约2.5秒 10% 开场缓推（25fps）；用户上传 BGM 后循环、淡入淡出、音量控制，上传音效后在单个指定时间混音。以上设置均由 FFmpeg/libass **真正写入最终 MP4**，不只是 JSON 或 HTML 假演示。
- UI：真实工作台 `http://127.0.0.1:8990/` 新增「视频包装｜字幕 · 花字 · 动画 · 配乐」操作面板。使用顺序：导入→人工核对片段/字幕→设置花字、上传有授权音频→点“渲染成片”→下载并预览 MP4、SRT 与质检报告；花字时间是**剪辑后成片的时间**。旧规则模拟保留在 `/demo`。
- 核心新增：`package_render.py`、`web/packaging.js`、`tests/test_packaging_real.py`；同步编辑 `media_workflow.py`、`media_server.py`、`web/workbench.html`、`tests/test_media_http.py`。输出的包装成片为 `final_video.mp4`，独立 SRT 仍可下载。
- 真实自动化测试生成无版权音视频，验证 ASS 字幕/花字的最终画面有非黑色文字像素、开场缓推开启、最终含音轨、BGM/SFX 混音、时长符合预期和包装报告正确；HTTP 也实测上传 BGM、保存花字、实际导出并下载。总计18项测试通过；Edge 无头真实打开网页，并显示包装控件及 FFmpeg 就绪状态；主界面内联及外链 JS 通过 Node 语法检查。
- 本次发现 8990 有两个残留 Python 监听进程，用户可能随机进入旧版页面；已终止 17:39 启动的旧监听 PID 15968，保留18:09新服务 PID 24732；验证 8990 的 `/packaging.js` 返回 HTTP 200、主页面包含包装面板。后续如果看见旧版先确认浏览器是否在 `/demo`，再打开根路径 `/` 并刷新。
- 严格边界：仍无法自动可靠判断 IP/操盘手、口误或错误 take，亦不会自动生成花字内容、自动匹配贴纸/模板/音效；字幕和花字精细美术效果仍需对真实视频逐条审片，目前 SFX 仅支持单文件/单时间触发；没做原项目所要求的全部自动包装模板。不能说成完整商业自动化视频剪辑产品。
